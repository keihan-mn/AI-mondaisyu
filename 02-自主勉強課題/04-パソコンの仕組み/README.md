# パソコンの仕組み 初心者向け学習問題

この教材は、パソコンの内部でOS、アプリ、CPU、メモリー、ストレージ、プロセスがどのように連携しているかを、日常の操作やコーディング中の場面と結び付けて学ぶためのものです。

用語を暗記するだけでなく、「アプリを起動する」「ウィンドウを閉じる」「複数のアプリを使う」といった操作の裏で何が起きているかを、自分の言葉で説明できることを目指します。

## 回答するときの共通ルール

各問題について、次の内容を含めて回答してください。

1. 調べて分かったこと
2. 初心者にも伝わる、自分の言葉での説明
3. 問題で求められた日常操作の例、比較、または観察結果
4. 自分の判断を求められた場合は、その判断と理由
5. 参考にした情報源

実際のパソコンを観察する問題では、知らないプロセスの停止や設定変更は行わないでください。また、画面に個人名やファイルの保存場所などが表示された場合は、回答へ不用意に転載しないでください。

## 第1章　パソコンの中の役割分担

### 問題1：ハードウェア・OS・アプリは何を担当するのか

パソコンを構成するものは、大きく「ハードウェア」と「ソフトウェア」に分けられます。ハードウェアはキーボードや画面などの物理的な機器、ソフトウェアはOSやアプリなどのプログラムです。OSは、ハードウェアとアプリの間に立ち、パソコン全体を管理する基本的なソフトウェアです。

キーボードで文字を入力し、エディタやメモ帳の画面にその文字が表示される場面を考えてください。初心者向けの大まかな説明として、次のものがそれぞれ何を担当するか説明してください。

- キーボードなどの入力装置
- OS
- エディタやメモ帳などのアプリ
- 画面などの出力装置

次に、一般的なパソコンで、普段使っているOSが起動していない場合、そのアプリをいつもどおり利用できるか考えてください。OSが必要だと思う理由も説明してください。

> **ヒント：**「ハードウェア ソフトウェア 違い」「OS 役割」「アプリケーションソフト」「入力装置 出力装置」というキーワードを使って調べてください。

### 問題2：CPU・メモリー・ストレージは何が違うのか

この問題では、次の3つの部品について学びます。

- CPU：プログラムの命令を実行し、計算や処理を行う部品
- メモリー：実行中のプログラムや使用中のデータを一時的に置く場所。この教材では主にRAMを指します
- ストレージ：アプリやファイルを長く保存する場所。SSDやHDDなどがあります

CPU、メモリー、ストレージの違いを調べ、次の場面でそれぞれがどのような役割を持つか、比較表にまとめてください。

1. 保存されている写真編集アプリを起動する
2. 大きな写真を開いて編集する
3. 編集した写真を保存する
4. 通常の手順でパソコンをシャットダウンする

また、3つの役割を机、作業する人、書棚などの身近なものにたとえて説明してください。たとえは理解の助けになりますが、実際の仕組みを完全には表せません。自分のたとえが実際の仕組みと異なる点も一つ挙げてください。

> **ヒント：**「CPU 役割」「RAM メモリー」「SSD HDD ストレージ」「メモリー ストレージ 違い」「RAM 揮発性」というキーワードを使って調べてください。

### 問題3：電源を入れてコードファイルを保存するまで、何が連携するのか

パソコンの電源を入れてから、エディタでコードファイルを作成して保存するまでには、OS、CPU、メモリー、ストレージが連携しています。

次の操作を順番に並べ、それぞれの段階で何が主に働いているかを説明してください。

- パソコンの電源を入れる
- OSが起動する
- ログインする
- エディタを起動する
- コードを書く
- コードファイルを保存する

この問題では、ファームウェアやブートローダーなど、電源投入直後の詳しい技術までは説明しなくて構いません。初心者向けの基本的な流れに絞ってください。

最後に、コードを書いたものの、まだ保存していない状態と、ファイルとして保存した後の状態を比較してください。データが主にメモリーにある状態と、ストレージへ保存された状態では、アプリの終了やパソコンの電源断による影響がどのように違うか説明してください。

> **ヒント：**「パソコン 起動 流れ」「OS ブート 初心者」「アプリ 起動 仕組み」「未保存データ メモリー」「ファイル 保存 RAM SSD」というキーワードを使って調べてください。

## 第2章　アプリを起動・終了すると何が起こるのか

### 問題1：保存されたアプリと実行中のプロセスは何が違うのか

「プログラム」は、パソコンに行わせる命令を記述したものです。「プロセス」は、プログラムが実行されているときに、OSが管理する処理の単位です。PID（プロセスID）は、OSが実行中のプロセスを区別するために付ける番号です。

ストレージに保存されているエディタと、そのエディタを起動した後のプロセスには、どのような違いがあるでしょうか。アプリアイコンを押す前と押した後を比較し、ストレージ、メモリー、CPUがどのように関係するか説明してください。

ただし、1つのアプリと1つのプロセスが必ず対応するわけではありません。1つのアプリが複数のファイルで構成される場合や、複数のプロセスを起動する場合があることも調べてください。また、プロセスは実行中であっても、入力や通信を待っていてCPUをほとんど使わないことがあります。

最後に、「レシピと、実際に行われている調理」などを参考に、自分なりのたとえでプログラムとプロセスの違いを説明してください。そのたとえでは表せない点も一つ挙げてください。

> **ヒント：**「プログラム プロセス 違い」「アプリ 起動 メモリー」「プロセスID PID」「アプリ 複数プロセス」「プロセス 待機状態」というキーワードを使って調べてください。

### 問題2：ウィンドウを閉じる・アプリを終了する・強制終了するの違い

次の3つの操作は、同じ結果になるとは限りません。

- ウィンドウを閉じる
- アプリを通常の手順で終了する
- アプリを強制終了する

自分が使用しているOSと、普段使っているアプリを一つ選び、それぞれの操作を次の観点から比較してください。OS、アプリ、設定によって動作が異なるため、「どのパソコンでも必ず同じ」と決めつけずに調べてください。

- ウィンドウはどうなるか
- プロセスは動き続けるか
- 未保存の内容はどうなるか
- そのプロセスに割り当てられていたメモリーは、OSが再利用できる状態になるか
- 更新用などの補助プロセスが残る場合はあるか

比較のために実際の操作を試す場合は、重要な作業中のアプリを使わず、保存済みのテスト用ファイルで確認してください。

最後に、アプリが応答しなくなった場面を想定し、どのような順番で対処するかを考えてください。強制終了を最初の手段にしない方がよい理由と、強制終了が必要だと判断する条件も説明してください。

> **ヒント：**「ウィンドウ 閉じる アプリ 終了 違い」「自分のOS名 アプリ 終了」「タスク終了 強制終了」「未保存データ 強制終了」「プロセス終了 メモリー」というキーワードを使って調べてください。

### 問題3：画面に見えないプロセスは何をしているのか

この問題では、画面上で現在操作しているアプリや処理を「前面」、画面に表示されていなくても補助的に動く処理を「バックグラウンド」と呼びます。バックグラウンドのプロセスも、常にCPUを使い続けているとは限らず、通知や入力などを待っている時間があります。

音楽の再生、クラウドへのファイル同期、通知の受信、アプリの更新などを例に、画面に見えないプロセスが必要な理由を説明してください。

次に、WindowsのタスクマネージャーまたはmacOSのアクティビティモニタを開き、自分で起動したブラウザ、エディタ、音楽アプリなどに関係するプロセスを3つ観察してください。それぞれについて、次の内容をまとめてください。

1. 表示されたプロセス名
2. 何をしているプロセスだと予想したか
3. 予想の根拠
4. 公式情報などを調べて分かったこと

この問題では観察だけを行い、プロセスの停止や設定変更はしないでください。また、プロセス名だけで役割や安全性を断定してはいけない理由と、提供元や公式情報を確認する方法を考えてください。

> **ヒント：**「バックグラウンドプロセス」「Windows タスクマネージャー プロセス」「macOS アクティビティモニタ プロセス」「プロセス 提供元 確認」「システムプロセス 終了 危険」というキーワードを使って調べてください。

## 第3章　複数のアプリはどのように同時に動くのか

### 問題1：1つのCPUコアで複数の処理が動いて見えるのはなぜか

OSには、どのプロセスがCPUを使うか、その順番や時間を調整する「スケジューリング」という仕組みがあります。

音楽を再生しながら、エディタへ文字を入力し、ブラウザでファイルをダウンロードする場面を考えてください。1つのCPUコアは、基本的にある瞬間には1つの処理を実行します。それでも複数の処理が同時に進んでいるように見える理由を、OSによる処理の切り替えと結び付けて説明してください。

次に、次の2つの違いを説明してください。

- 並行処理：複数の処理を、切り替えながら少しずつ進めること
- 並列処理：複数のCPUコアなどを使い、複数の処理を同じ時点で実行すること

実際のパソコンには複数のCPUコアがある場合が多く、処理によっては入力、ストレージ、ネットワークなどを待つ時間もあります。「すべてがCPUの高速な切り替えだけで実現している」とは限らないことも含めて、最初の場面を説明してください。

> **ヒント：**「CPU スケジューリング」「タイムスライス」「並行処理 並列処理 違い」「CPU コア」「CPU I/O 待ち」というキーワードを使って調べてください。

### 問題2：プロセスとスレッドはどう違うのか

プロセスはOSが管理する実行中の処理の単位で、通常はほかのプロセスとメモリー空間が分けられています。「スレッド」は、1つのプロセス内にある処理の流れです。同じプロセス内のスレッドはデータを共有しやすい一方、一つの不具合が同じプロセス内の別の処理へ影響する場合があります。

次の2つを比較し、それぞれの利点と注意点を説明してください。

- 処理を別々のプロセスに分ける
- 1つのプロセス内で複数のスレッドに分ける

ブラウザではタブや機能の一部を別プロセスに分けることがありますが、その構成はブラウザ、OS、設定、バージョンによって異なります。一律に「1つのタブが必ず1つのプロセスになる」と考えてはいけない理由も説明してください。

最後に、自分がエディタを設計すると仮定します。画面操作、自動保存、動画変換のような重い処理を、どのように分けたいか考えてください。この設計判断に唯一の正解はありません。別プロセスまたは別スレッドに分ける利点と問題点を比較し、自分の判断と理由を書いてください。

> **ヒント：**「プロセス スレッド 違い」「プロセス メモリー空間」「マルチスレッド メリット デメリット」「ブラウザ マルチプロセス」「スレッド データ共有」というキーワードを使って調べてください。

### 問題3：コーディング中に重い処理が動いたら、どう判断するか

エディタ、ターミナル、開発サーバー、ブラウザを同時に使っているとき、コードから実行した計算処理がCPUを多く使い始めたとします。開発サーバーとは、開発中のWebページなどをブラウザへ届けるために、自分のパソコン上で動かすプログラムです。

まず、エディタ、ターミナル、開発サーバー、ブラウザが、それぞれ別のプロセスとして動く場合の関係を図や箇条書きで表してください。そのうえで、一つの計算処理のCPU使用率が高くても、ほかのアプリを操作できる場合がある理由を、CPUコアとスケジューリングから説明してください。

ただし、開発サーバーは起動中でも、通信を待っている間はCPU使用率が低いことがあります。また、待機を含まず計算を繰り返すループはCPU負荷が高くなりやすい一方、入力待ちや休止を含むループはCPUをほとんど使わないことがあります。この違いも説明してください。

最後に、CPU使用率が高く、パソコンの反応が遅くなった場面で、次の対処をどのように使い分けるか考えてください。

- 処理の完了を待つ
- ターミナルで通常の停止操作を行う
- 保存状況を確認してアプリを通常終了する
- 最後の手段として強制終了する

ターミナルで前面実行中の処理に中断を依頼する代表的な操作として、`Control + C`があります。各対処が適している状況、失う可能性のあるデータ、自分が選ぶ順番とその理由を書いてください。実際に負荷の高いループを作って試す必要はありません。

> **ヒント：**「CPU 使用率 高い 原因」「OS スケジューリング マルチコア」「開発サーバー プロセス」「待機なし ループ CPU使用率」「ターミナル Control C プロセス停止」というキーワードを使って調べてください。

## 第4章　メモリーは何に使われているのか

### 問題1：アプリを開くとメモリーはどのように使われるのか

第1章では、メモリー（主にRAM）が、実行中のプログラムや使用中のデータを一時的に置く場所であることを学びました。この章では、実際のアプリがメモリーをどのように使うかを詳しく考えます。

アプリを起動すると、実行に必要なコードやデータが必要に応じてメモリーへ置かれます。アプリ全体が必ず一度にメモリーへ読み込まれるわけではありません。次の場面を比較し、メモリー使用量が増減する理由を説明してください。

- エディタだけを起動している
- ブラウザでタブを一つ開いている
- ブラウザで複数のタブを開いている
- 写真編集アプリで大きな画像を開いている

ブラウザのタブ数とメモリー使用量は、必ず単純な比例関係になるとは限りません。複数のタブで共有されるデータや、使っていないタブを休止する機能についても調べてください。また、圧縮された画像ファイルの保存容量と、画像を開いて展開した後のメモリー使用量が同じとは限らない理由も説明してください。

重要な作業を保存したうえで、タスクマネージャーまたはアクティビティモニタを使い、普段使うアプリを一つだけ観察してください。この問題では観察だけを行い、未知のプロセスの停止や設定変更はしないでください。次の内容を記録してください。

1. アプリを起動する前後で、メモリー使用量がどう変化したか
2. ファイルやタブを開いたとき、どう変化したか
3. 保存して通常の方法で閉じたとき、どう変化したか

アプリを閉じても、キャッシュやOSによる再利用のため、表示上の空きメモリーがすぐ増えるとは限りません。CPU使用率とメモリー使用量の違いも調べ、「CPU使用率は低いが多くのメモリーを使う例」と「CPU使用率は高いがメモリー使用量は比較的小さい例」を一つずつ考えてください。

最後に、メモリーが不足してきた場合、どのアプリやタブを先に閉じるかを考えてください。使用量だけでなく、未保存の作業、現在必要か、後で再開しやすいかという観点から判断理由を書いてください。

> **ヒント：**「アプリ RAM 使用量」「ブラウザ タブ メモリー」「画像 展開後 メモリー 使用量」「CPU使用率 メモリー使用量 違い」「メモリー キャッシュ」というキーワードを使って調べてください。

### 問題2：メモリーが足りなくなると何が起こるのか

「仮想メモリー」は、アプリに対して、それぞれが利用できるメモリー空間を提供する仕組みです。「スワップ」は、RAM上のデータの一部をストレージ側へ一時的に退避させる仕組みです。仮想メモリーとスワップは関係していますが、同じ意味ではありません。

メモリーの使用が増えると、OSは不要なキャッシュの再利用やメモリー圧縮などを行い、それでも必要な場合は一部をスワップ領域へ退避することがあります。具体的な順序や仕組みはOSによって異なります。また、スワップへの読み書きが大量に続くと、RAMだけを使う場合より処理が遅くなりやすくなります。

アプリやブラウザのタブを増やしたときに、次のような変化が起こる可能性について調べ、原因と結果の関係を図や箇条書きで説明してください。

- メモリーの使用量や負荷が高くなる
- スワップやページファイルの使用量が増える
- アプリの切り替えや操作が遅くなる
- アプリが終了したり、メモリー不足の警告が表示されたりする

macOSでは「メモリープレッシャー」、Windowsではメモリーの使用量、コミット済み、ページファイルなど、OSによって表示項目や名称が異なります。単純な「空きメモリー」の数値だけでは、メモリー不足を判断しにくい理由も説明してください。

最後に、次の3つの状況について、自分なら何をどの順番で確認し、どのように対処するか考えてください。この判断に唯一の正解はありません。

1. 一時的に大きな処理を実行している
2. 特定のアプリのメモリー使用量だけが増え続けている
3. メモリーだけでなくストレージの空き容量も少ない

「作業を保存して不要なアプリを通常終了する」「パソコンを再起動する」「ストレージの空きを確保する」「機種によって可能ならRAMを増設する」を比較してください。再起動は一時的な状態を解消できても、原因そのものを直すとは限らず、未保存の内容を失う可能性があることにも注意してください。

> **ヒント：**「仮想メモリー スワップ 違い」「macOS メモリープレッシャー スワップ」「Windows コミット済み ページファイル」「メモリー圧縮」「メモリー不足 対処」というキーワードを使って調べてください。

### 問題3：メモリーリークはどのように見つけて対処するのか

「メモリーリーク」とは、アプリにとって不要になったデータをプログラムが参照し続けるなどの理由で、そのメモリーを実行環境やOSが再利用できず、使用量が意図せず増えていく問題です。

一部のプログラミング言語には、不要になったメモリーを実行環境が自動的に回収する「ガベージコレクション」という仕組みがあります。ただし、この仕組みがある言語でも、不要なデータへの参照が残っていればメモリーリークは起こり得ます。

次の3つを比較し、メモリー使用量が増えたという事実だけでは、メモリーリークと断定できない理由を説明してください。

- 処理中だけ必要になる一時的なデータ
- 再利用するために保持されるキャッシュ
- 同じ操作を繰り返すたび、処理終了後も使用量が増え続けるメモリーリークの疑い

開発サーバーを長時間使い、同じ操作を繰り返すたびにメモリー使用量が増えている場面を想定してください。実際に大量のメモリーを消費する実験は行わず、次の観点を含む観察計画を作ってください。

1. どの操作を、同じ条件で何回か繰り返すか
2. 処理の前後で何を記録するか
3. 操作をやめて待った後、使用量がどうなるか
4. 開発サーバーを再起動した後、どう変化するか

OSの監視ツールは異常の手掛かりを得る道具であり、原因となるコードを確定する道具ではありません。再起動による一時的な対処と、コード、設定、依存ライブラリを調査・修正する根本的な対処を分けて説明してください。

「メモリープロファイラ」は、どのデータがメモリーに残っているかを詳しく調べる開発用ツールです。この問題では発展的な用語として役割を調べるだけで、実際の操作方法を覚える必要はありません。

> **ヒント：**「メモリーリーク とは」「メモリー使用量 増え続ける」「ガベージコレクション メモリーリーク」「メモリープロファイラ」「開発サーバー メモリー」というキーワードを使って調べてください。

## 第5章　ファイルを開く・保存するとは何か

### 問題1：OSはファイルとフォルダーをどう管理しているのか

「ファイルシステム」は、ストレージ上のファイルやフォルダーを整理し、名前、場所、サイズ、更新日時、アクセスの許可などを管理する仕組みです。「パス」は、ファイルやフォルダーの場所を表す文字列です。

エディタでコードファイルを開く場面を例に、エディタがOSへファイルの読み出しを依頼し、OSが指定されたパスを使ってファイルを探し、内容をアプリへ渡すという基本的な流れを説明してください。次の3つは何を表すのか、それぞれ分けて考えてください。

- ファイル名
- ファイルの場所を表すパス
- ファイルに保存されている内容

「絶対パス」は、ファイルシステム上の基準となる位置から場所を表します。「相対パス」は、現在の基準となるフォルダーから見た場所を表します。プログラム実行時には、この基準を「カレントディレクトリ」と呼びます。

架空のプロジェクトを使って、`src/app.js`というファイルを表す絶対パスと相対パスの例を作り、両者を比較してください。WindowsとmacOS・Linuxではパスの書き方が異なり、相対パスの基準は必ずしもプロジェクトの一番上とは限りません。回答には、自分の利用者名などを含む実際のパスを載せないでください。

また、次の3種類のエラーについて、考えられる原因と最初に確認することを比較してください。

- 指定したファイルが存在しない
- 別の場所にある同名ファイルを開いている
- ファイルを読む、変更する、または実行する権限がない

権限とは、誰がファイルを読み、変更し、実行できるかをOSが制御する仕組みです。拡張子はファイル名の一部であり、種類を示す手掛かりにはなりますが、ファイル内容を保証するものではありません。ファイル名の大文字と小文字を同じものとして扱うかも、ファイルシステムや設定によって異なります。

> **ヒント：**「ファイルシステム とは」「絶対パス 相対パス」「カレントディレクトリ」「拡張子 役割」「ファイル 読み取り 書き込み 実行 権限」というキーワードを使って調べてください。

### 問題2：編集した内容はいつストレージに保存されるのか

第1章では、エディタで書いたコードを保存する基本的な流れを学びました。この問題では、未保存の編集内容、ローカルファイルへの保存、自動保存、クラウド同期の違いを詳しく考えます。

初心者向けの基本的な流れとして、次の順番を説明してください。

1. エディタ内でコードを編集する
2. アプリがOSへ保存を依頼する
3. OSが書き込みを管理する
4. ストレージ上のファイルが更新される

アプリによっては、未保存内容を復元するため、一時ファイルなどへデータを書き込むことがあります。また、OSは書き込みを効率化するため、一時的にメモリー上の「書き込みキャッシュ」へデータを保持する場合があります。保存完了の表示と物理的な媒体への書き込み完了の詳しい関係は、OS、アプリ、ストレージによって異なります。この問題では、書き込みキャッシュの詳しい実装を覚える必要はありません。

次の保存方法を比較し、それぞれが「どのファイルを」「いつ」更新するのかを説明してください。

- 上書き保存
- 別名で保存
- 自動保存

自動保存が元のファイルを更新するのか、復元用のコピーを作るのかは、アプリによって異なります。また、ローカルファイルへの保存とクラウドへの同期は別の段階です。保存済みでも同期が完了していない場合があり、同期、変更履歴、バックアップも同じものとは限りません。

最後に、「アプリが突然終了した」「保存直後に電源が切れた」「同じファイルを別の端末から編集して同期が競合した」という3つの場面を比較し、自分ならデータを失わないために何をどの順番で確認するか説明してください。

> **ヒント：**「エディタ 未保存データ 復元」「ファイル 保存 仕組み」「OS 書き込みキャッシュ」「自動保存 上書き保存 違い」「ローカル保存 クラウド同期 違い」というキーワードを使って調べてください。

### 問題3：コピー・移動・削除では何が変わるのか

ファイルのコピー、移動、削除は、見た目が単純でも、保存場所や操作方法によってOS内部の処理が異なる場合があります。

次の基本的な違いを調べ、ファイルの場所、内容、元のファイルが残るかという観点から比較してください。

- コピー：通常は、元とコピー先が別のファイルとして扱われる。ただし、内部でデータをどのように保持するかはファイルシステムによって異なる
- 同じファイルシステム内での移動：場所を示す管理情報だけを変更できる場合が多い
- 別のストレージへの移動：コピーしてから元を削除する動作になる場合が多い
- 削除：ゴミ箱へ移す場合と、ファイルシステムの管理対象から外す場合がある

削除したデータが即座に完全消去されない場合があっても、安全に復元できるとは限りません。この教材では、機密データを完全に消去する方法までは扱いません。

次に、コードプロジェクト内のファイルをコピー、移動、削除した場合に、次のものへどのような影響が出るか考えてください。

- ほかのコードからの読み込みを指定する記述
- 設定ファイルや画像への参照パス
- 実行中のアプリや開発サーバー
- Gitが表示する変更内容

実行中のプログラムがファイルをすでに読み込んでいる場合、元のファイルを移動・削除しても一時的に動き続けることがあります。ただし、再読み込みや再起動をしたときに失敗する可能性があります。動作はOSやアプリによって異なります。

Gitは、変更前後の内容からファイル名の変更や移動を推測することがありますが、移動を必ず特別な情報として記録するわけではありません。この点を調べ、ファイル移動の前後に`git status`や差分を確認する理由を説明してください。

最後に、重要なコードファイルを別フォルダーへ移すときの安全な確認手順を作ってください。実際に操作を試す場合は、新しく作った学習用ファイルだけを使い、既存のプロジェクト、教材、回答ファイルは削除しないでください。

> **ヒント：**「ファイル コピー 移動 違い」「同一ドライブ 別ドライブ 移動」「ファイル 削除 ゴミ箱 仕組み」「ファイル パス 変更」「Git ファイル 移動 差分」というキーワードを使って調べてください。

## 第6章　ライブコーディングの裏で動くプロセス

### 問題1：ターミナルでコマンドを実行すると何が起こるのか

「ターミナル」は、文字を使ってパソコンを操作するための画面です。「シェル」は、ターミナルへ入力された文字をコマンドとして解釈するソフトウェアです。「カレントディレクトリ」は、コマンドが現在の基準としているフォルダーです。

シェルが入力を解釈した後の動作は、コマンドの種類によって異なります。`cd`のようにシェル自身が処理する「内部コマンド」では、通常、新しいプロセスを起動しません。別のプログラムを実行する「外部コマンド」では、シェルがOSへ依頼し、新しいプロセスを起動します。

自分のOSでフォルダーの場所や内容を確認する、読み取り中心のコマンドを調べ、次の流れを説明してください。

1. 利用者がターミナルへコマンドを入力する
2. シェルが入力内容を解釈する
3. 内部コマンドならシェル自身が処理し、外部コマンドならOSへプログラムの起動を依頼する
4. 結果やエラーがターミナルに表示される

macOS・Linuxでは`pwd`や`ls`が一般的です。WindowsのPowerShellでは同じ名前が別名や異なる仕組みで提供される場合があり、コマンドプロンプトでは`dir`などを使います。使用しているOSとシェルに合う公式情報を確認してください。

「PATH」は、外部コマンドを探すフォルダーの一覧をシェルへ伝える設定です。次のエラーについて、考えられる原因と、自分なら最初に何を確認するかを比較してください。

- コマンドが見つからない
- 指定したファイルが見つからない
- ファイルやコマンドを利用する権限がない

インターネットで見つけた未知のコマンドや、管理者権限を求めるコマンドを、意味を確認せずに実行してはいけない理由も説明してください。

> **ヒント：**「ターミナル シェル 違い」「シェル 内部コマンド 外部コマンド」「コマンド 実行 プロセス」「カレントディレクトリ」「PATH 環境変数」「permission denied 原因」というキーワードを使って調べてください。

### 問題2：保存したコードがブラウザへ反映されるまで

Web開発では、エディタでコードを保存すると、開発中の画面が自動的に更新されることがあります。この処理には、次の仕組みが関係します。

- ファイル監視：対象ファイルの変更を開発ツールが検知する仕組み
- ビルド：ソースコードを必要に応じて変換、結合、検査する処理
- 開発サーバー：開発中のページやデータを自分のパソコン上でブラウザへ提供するプログラム
- ホットリロード：変更を検知し、ページ全体または一部へ自動的に反映する仕組み

エディタでコードを変更してからブラウザへ反映されるまでの基本的な流れを、次の要素を使って図や箇条書きで説明してください。

1. エディタがファイルを保存する
2. 開発ツールがファイルの変更を検知する
3. 必要な場合はビルドを実行する
4. 開発サーバーが新しい内容を提供する
5. ブラウザが新しい内容を受け取り、画面を更新する

すべての開発環境で、ビルド、ファイル監視、自動更新が行われるとは限りません。利用するツールによって、どの処理が必要かは異なります。

コードを変更したのにブラウザの表示が変わらない場面を想定し、次の原因をどのような順番で確認するか、切り分け手順を作ってください。

- ファイルをまだ保存していない
- 別のファイルや別のプロジェクトを編集している
- ファイル監視や開発サーバーが停止している
- ビルドエラーが発生している
- 違うURLやポートの開発サーバーを見ている
- ブラウザに古い内容がキャッシュされている

最初からキャッシュや依存ファイルを削除するのではなく、保存状態、編集したファイルのパス、開発サーバーを起動したターミナルのログ、ブラウザのURLを先に確認する理由を説明してください。ターミナルに出るビルドのエラーと、ブラウザの開発者ツールに出る実行時のエラーの違いも調べてください。

> **ヒント：**「開発サーバー ファイル監視」「ホットリロード 仕組み」「Web開発 ビルド とは」「開発サーバー ログ」「ブラウザ 開発者ツール Console」「ブラウザ キャッシュ 更新されない」というキーワードを使って調べてください。

### 問題3：開発サーバーを安全に起動・停止し、問題を切り分けるには

「ポート番号」は、OSが同じパソコン上のどの通信サービスへデータを届けるかを区別するための番号です。プロセスそのものを区別するPIDとは別物です。また、あるプロセスが別のプロセスを起動したとき、起動元を「親プロセス」、起動された側を「子プロセス」と呼びます。

Web開発で使われることの多い`npm run dev`を例に、次の関係を図や箇条書きで表してください。

`ターミナル → シェル → npm → package.jsonに登録されたスクリプト → 開発ツールや開発サーバー`

`npm run dev`は、`package.json`の`dev`というスクリプトに書かれたコマンドを実行します。Node.js製の開発ツールやサーバーが起動する構成は多くありますが、必ずNode.jsのサーバーを直接起動するとは限りません。また、npmスクリプトには任意の処理を書けるため、他人から受け取ったプロジェクトでは、スクリプトの内容を確認してから実行する理由も説明してください。

`Control + C`は、ターミナルで前面実行中の処理へ中断を依頼する代表的な操作です。プログラムやOSによって、終了処理や内部の仕組みは異なります。ターミナルを閉じた場合も、構成や起動方法によっては子プロセスやバックグラウンドの処理が残ることがあります。

次の問題について、確認と対処の手順を作ってください。

- 「ポートはすでに使用されています」と表示される
- `Control + C`を押した後も、開発サーバーが動いているように見える
- 同じ開発サーバーを複数回起動した可能性がある

手順には、次の観点を含めてください。

1. 開発サーバーを起動したターミナルとログを確認する
2. 使用中のポート番号、PID、コマンド名、起動元のフォルダーを照合する
3. 別のプロジェクトや必要なサービスではないか確認する
4. 通常の停止操作を優先する
5. 強制終了は、対象を確認したうえで最後の手段として使う

未知のプロセスを名前だけで停止したり、インターネットで見つけた強制停止コマンドを意味を確認せず実行したりしてはいけない理由も説明してください。この問題では「シグナル」や強制停止の詳しい内部実装を覚える必要はありません。

> **ヒント：**「npm scripts package.json」「npm run dev プロセス」「ポート番号 PID 違い」「macOS ポート 使用中 プロセス 確認」「Windows ポート PID 確認」「Control C プロセス 中断」「親プロセス 子プロセス 違い」というキーワードを使って調べてください。

## 第7章　パソコンの状態を観察して問題を切り分ける

この章では、第1章から第6章で学んだOS、CPU、メモリー、ストレージ、ファイル、プロセスの知識を組み合わせます。新しい用語を覚えるだけでなく、「観察する」「仮説を立てる」「状態を変えない方法から確認する」「根拠を得てから対処する」「正常になったか確かめる」という流れで、問題を安全に切り分けることを目指します。

### 問題1：CPU・メモリー・ディスクの表示から何が分かるのか

WindowsのタスクマネージャーやmacOSのアクティビティモニタでは、プロセスごとのCPU、メモリー、ディスク、ネットワークなどの状態を確認できます。ここでいう「ディスク」は監視画面で使われる表示名で、SSDなどのストレージへの読み書きを表します。

第4章ではメモリーの仕組みを学びました。この問題では、メモリーだけでなく、複数の指標を組み合わせて症状との関係を観察します。自分のOSの公式情報を調べ、次の表を作ってください。

| 指標 | 何の活動を表すか | 高くなる正常な例 | 問題の兆候になる例 | 数値だけでは断定できない理由 | あわせて確認する項目 |
|---|---|---|---|---|---|
| CPU |  |  |  |  |  |
| メモリー |  |  |  |  |  |
| ディスク |  |  |  |  |  |
| ネットワーク |  |  |  |  |  |
| プロセスの状態 |  |  |  |  |  |

OSや表示画面によって、指標の名前や計算方法は異なります。たとえば、macOSでは複数のCPUコアを使う一つのプロセスが100%を超えて表示される場合があります。Windowsの「ディスク100%」は、単純にストレージの最大転送速度を使い切ったことだけを意味するとは限りません。表示された読み書きの値が、瞬間的な速度か起動後の累計かも確認する必要があります。

メモリープレッシャーは主にmacOSで使われる表示で、Windowsでは利用可能メモリーやコミット済みなど別の項目を確認します。ネットワーク通信があることだけで、不正な通信や不具合とは判断できません。「待機中」や「スリープ中」などのプロセス状態も、仕事がない間に待っている正常な状態の場合があります。

次に、大切な作業を保存してから、自分で起動した提供元の分かるアプリを一つ観察してください。この問題では、読み取りだけを行います。意図的に高い負荷を発生させたり、プロセスを停止したり、設定を変更したりしないでください。

1. 操作する前
2. アプリを起動した直後
3. ファイルやページを開いたとき
4. 処理が終わって少し待った後

各時点で、CPU、メモリー、ディスクなどの変化と、画面上の動きを記録してください。OSのバックグラウンド処理も同時に動くため、変化した数値がすべて対象アプリの影響とは限りません。スクリーンショットやプロセス一覧を回答へ載せる場合は、利用者名、ファイルパス、文書名などを隠してください。

最後に、一時的に高い数値が出た場合と、操作の遅さと同時に高い状態が続く場合を比較してください。「症状と同時に起きたか」「どのくらい続いたか」「普段との差があるか」に加えて、処理の目的、進行状況、未保存の内容を確認し、待つか、保存して通常終了するかをどのように判断するか説明してください。

> **ヒント：**「Microsoft タスクマネージャー CPU 使用率 見方」「Apple アクティビティモニタ CPU パーセント」「Windows ディスク アクティブな時間」「macOS メモリプレッシャー」「プロセス 待機状態」というキーワードを使って調べてください。

### 問題2：アプリが応答しないとき、待つ・終了・再起動をどう判断するか

第2章では、ウィンドウを閉じる、アプリを通常終了する、強制終了するという操作の違いを学びました。この問題では、実際の症状と失う可能性のあるデータを確認し、どの対処を選ぶか考えます。

「応答なし」は一般に、OSがアプリの画面処理などから一定時間応答を得られず、操作に反応していないと判断した状態です。具体的な判定方法や表示はOSによって異なり、必ずしもアプリがすでに終了しているわけではありません。

アプリが応答しなくなる原因として、次のような可能性があります。

- 時間のかかる計算を続けている
- I/Oを待っている。I/O（入出力）とは、ストレージやネットワークなどとのデータのやり取りです
- メモリーが不足している
- アプリや追加機能に不具合がある
- 複数の処理が互いの完了を待ち続けている。これを「デッドロック」と呼びます

CPU使用率が高ければ重い計算を続けている可能性がありますが、正常な処理かもしれません。CPU使用率が低い場合も、ストレージ、ネットワーク、別の処理からの応答を待っている可能性があります。メモリー使用量やログも手掛かりにはなりますが、一つの数値だけでは原因を断定できません。

エディタが「応答なし」になった場面を想定し、次の内容を確認する理由を説明してください。

- エディタだけが反応しないのか、パソコン全体が反応しないのか
- 進行状況や処理中の表示があるか
- CPU、メモリー、ディスクの状態はどうか
- ターミナルから起動した処理なら、該当するログが更新されているか
- 未保存のファイルや、保存・更新の途中のファイルがあるか

そのうえで、次の対処を比較し、判断フローチャートを作ってください。

1. 進行表示などを確認して少し待つ
2. アプリ内のキャンセル操作や、ターミナル上の通常の停止操作を試す
3. アプリのメニューから通常終了する
4. OSの機能を使って強制終了する
5. アプリだけでは回復せず、パソコン全体に問題がある場合は再起動を検討する

フローチャートの各段階には、「確認できた事実」「次の段階へ進む条件」「失う可能性のあるもの」を書いてください。Windowsのタスクマネージャーにある「タスクの終了」や、macOSの「強制終了」は、アプリのメニューから行う通常終了とは異なります。自動復元機能があっても、未保存の内容を必ず復元できるとは限りません。

保存や更新の途中で強制終了すると、最新の内容やファイルの状態が不完全になる場合があります。また、再起動で一時的に直っても、原因が解消された証拠にはなりません。OSやファームウェアの更新中は通常のアプリ停止とは分けて考え、安易に電源を切らないでください。電源ボタンを長押しする強制的な電源断は、通常の再起動よりさらに最後の手段です。

> **ヒント：**「アプリ 応答なし 原因」「CPU ディスク I/O 待ち」「アプリ 強制終了 未保存」「パソコン 再起動 一時的に直る」「デッドロック とは」というキーワードを使って調べてください。

### 問題3：原因を決めつけずにトラブルを切り分けるには

「切り分け」とは、考えられる原因について仮説を立て、条件を一つずつ確認して原因の範囲を狭めることです。「再現手順」は同じ問題を起こすための操作手順、「ログ」はプログラムの処理経過やエラーを記録したものです。

次の3つの場面について、それぞれ最低二つの仮説を立て、同じ形式の表へまとめてください。

- 多数のアプリを開いた後、パソコン全体が遅くなった
- コードを保存したが、ブラウザの表示へ変更が反映されない
- 開発サーバーを起動すると、「ポートはすでに使用されています」と表示される

表には、次の項目を設けてください。仮想的な場面なので、実際の結果ではなく、想定される確認結果と、その結果ごとの次の行動を書いてください。

| 項目 | 書く内容 |
|---|---|
| 観察できた症状 | 推測ではなく、画面やログで確認できた事実 |
| 考えられる仮説 | CPU、メモリー、プロセス、ファイル、パス、ポートなどに関する候補 |
| 仮説を考えた根拠 | どの事実と結び付けたか |
| 最初の確認 | ファイルや設定を変更せずに確認できること |
| 想定される結果 | どのような結果があり得るか |
| 次の確認 | 結果ごとに、次は何を確認するか |
| 根拠を得た後の対処 | 対象と影響を確認してから行う操作 |
| 正常化の確認 | 対処後に、何をもって直ったと判断するか |

一つ目の場面では、最初に「パソコン全体が遅いのか、特定のアプリだけが遅いのか」を確認してください。CPUを長時間使う処理、メモリー不足やスワップ、ストレージの大量読み書き、同期や更新などのバックグラウンド処理を、最初から一つに決めつけず比較してください。

二つ目の場面では、第6章で学んだ原因候補を並べるだけでなく、保存状態、編集したファイル、プロジェクト、URL、開発サーバー、ビルドエラーを、状態を大きく変えない順番で確認してください。

三つ目の場面では、ポートを使用しているプロセスをすぐ停止するのではなく、ポート番号、PID、コマンド名、起動元のフォルダーを照合してください。そのプロセスが自分で起動したものか、別の必要なサーバーではないかを確かめたうえで、「既存のサーバーを使う」「通常終了して起動し直す」「設定上可能なら別のポートを使う」を比較してください。

一度に複数の設定を変えると、どの変更が結果へ影響したか分からなくなります。キャッシュや依存関係を削除する場合も、根拠、対象、再作成する方法を確認する必要があります。「依存関係」とは、プロジェクトが動くために利用している外部ライブラリやツールです。知らないプロセスの停止や、根拠のないファイル削除を最初の対処にしない理由を説明してください。

AIへトラブルを相談する場合、次の情報をどのように整理すると原因の切り分けに役立つか考えてください。

- OS、アプリ、開発ツールの名前と、分かる場合はバージョン
- 問題が起きるまでの最小限の操作手順
- 正確なエラーメッセージと発生時刻
- 直前に変更したこと
- すでに試した確認、その結果
- 毎回起きるのか、時々起きるのか

一方、APIキー、パスワード、アクセストークン、Cookie、認証情報、利用者名を含む絶対パス、非公開URL、個人情報、顧客情報、公開できないコードやログは、そのまま共有してはいけません。必要な部分だけを残し、秘密情報を隠す「マスキング」が必要な理由を説明してください。

最後に、AIから提案されたコマンドを実行する前に確認する、自分用のチェックリストを作ってください。少なくとも、実行するフォルダー、読み取り・変更・削除の対象、影響する範囲、元に戻せるか、管理者権限の有無、外部へのデータ送信の有無を含めてください。

> **ヒント：**「トラブルシューティング 切り分け」「再現手順 ログ」「原因 仮説 検証」「シェル コマンド 実行前 確認」「最小権限 原則」「ログ 機密情報 マスキング」「APIキー ログ 共有 危険」というキーワードを使って調べてください。
